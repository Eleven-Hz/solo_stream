## 1. 채팅 생성 시 503 UNAVAILABLE (Gemini 서버 혼잡) ✅ 재시도+알림 구현됨

### 증상
채팅 생성 중 로그에 다음과 같은 오류가 찍히고, 해당 라운드의 봇 채팅이 비어서
화면에 채팅이 안 뜹니다.

```
[solo_stream.ai] [ERROR] 채팅 생성 실패: 503 UNAVAILABLE. {'error': {'code': 503,
'message': 'This model is currently experiencing high demand. ...', 'status': 'UNAVAILABLE'}}
```

### 원인
- 기본 채팅 모델인 `gemini-2.5-flash` 는 무료/공용 티어에서 트래픽이 몰리는
  시간대에 503(서버 혼잡)을 자주 반환합니다.
- (수정 전) `GeminiClient._call_with_retry()` 가 429/RESOURCE_EXHAUSTED 만 재시도하고
  503/UNAVAILABLE 은 재시도하지 않아, 503이 뜬 라운드는 채팅이 통째로 누락됐다.
- (수정 후, 2026-06-29) `_call_with_retry` 가 503 등도 짧게 재시도한다(아래 '현재 대응').
  재시도까지 모두 실패한 경우에만 `generate_chats()` 의 `except` 에 잡혀 빈 리스트를
  반환하고 그 회차만 누락된다. (앱이 죽지는 않음)

### 영향 범위
- **채팅 생성**: 재시도까지 실패한 경우만 해당 라운드 채팅 누락 (다음 라운드는 정상 시도).
- **Vision 분석**(`analyze_screenshot`)도 같은 `_call_with_retry` 로 재시도됨 →
  그래도 실패하면 `VISION_ERROR_MARKER` 로 처리되어 "화면 정보 없음"으로 진행.
- **게임 프로필 생성**(`game_profile_loader._search`)은 별개 경로이며, 한 단계가
  503으로 재시도까지 소진하고도 실패하면 **나머지 단계를 시도하지 않고 생성 전체를
  중단**한다(빈 껍데기 저장 방지). 재시도는 짧게 조정됨(3회, 2→4s). → 아래 5-1b 참고.

### 현재 대응
- **503 자동 재시도 구현됨 (2026-06-29).** `GeminiClient._call_with_retry` 가 이제
  기존 429 경로에 더해 **503/UNAVAILABLE/500/overloaded/internal error** 도 재시도한다
  (`_is_retryable_server_error()` 헬퍼로 판별, `src/ai/model_client.py`). 단 채팅은
  라운드 주기에 묶여 길게 끌면 라운드가 밀리므로 **짧은 백오프(1s→2s, 최대 2회 재시도)**
  로 제한했다. 429는 종전대로 서버 `retry in Ns` 힌트를 따른다. 마지막 시도까지 실패하면
  원본 예외를 그대로 raise → 기존 `last_chat_call.error` + `api_busy` 알림 경로가 동작.
  채팅·Vision 모두 같은 `_call_with_retry` 를 타므로 **함께 커버**된다.
  (Claude 경로는 anthropic SDK 가 자체 5xx/overloaded 재시도를 하므로 별도 작업 불필요.)
- **사용자 알림도 유지 (2026-06-29 새벽 작업).** 재시도까지 소진해 503이 끝내 실패하면
  사용자가 원인을 알 수 있도록 **채팅창 시스템 메시지**로 안내한다.
  - `model_client`: `ChatCallDebug.error` 필드와 `is_transient_error()` 헬퍼 추가.
    `generate_chats`(Gemini/Claude) 가 실패 사유를 `error` 에 기록하고,
    `is_transient_error()` 가 `503/unavailable/429/resource_exhausted/overloaded`
    문자열로 일시적 오류를 판별한다 (`model_client.py:201`).
  - `main.ai_process`: `api_busy` edge 감지로 **상태가 바뀔 때만** 채팅창에 1회씩
    안내 — 혼잡 시작 시 "⚠ AI 서버가 혼잡합니다(503 등) …", 회복 시 "✓ AI 서버
    연결이 회복됐습니다 …". 매 라운드 같은 메시지가 도배되지 않게 했다.
  - 알림 방식 변천: 처음엔 타이틀바 ⚠ 아이콘으로 띄웠으나(79749fa, `TitleBar.set_warning`
    을 출처별 dict 로 확장), "아이콘은 원인 파악이 어렵고 눈에 잘 안 띈다"는 피드백으로
    **채팅창 시스템 메시지로 변경**(3ca60e9). `TitleBar.set_warning` 은 다시 단순화되고
    `api_status` 분기는 제거됨. 프로필 생성 503 아이콘 알림도 제거(프로필 실패는
    기존 채팅 메시지로 이미 안내됨).
- 사용자가 취할 수 있는 임시 조치 (변동 없음):
  1. 잠시 후 자동으로 다음 라운드에 다시 시도되므로 기다린다.
  2. 503이 지속되면 **AI 모델 탭에서 채팅 모델을 변경**한다
     (예: `gemini-2.5-flash-lite` 또는 `gemini-2.0-flash`, 혹은 Claude provider).
  3. 유료 티어/별도 API 키 사용 시 503 빈도가 크게 줄어든다.

### 향후 개선 후보 (미구현)
- Vision 분석(`analyze_screenshot`)은 재시도는 되지만 아직 503 **알림** 경로엔 미포함
  (채팅 경로만 `api_busy` 안내). 재시도까지 실패하면 여전히 조용히 "화면 정보 없음" 처리.
- 반복 503 시 사용자에게 "채팅 모델을 바꿔보라"는 구체적 안내를 1회 노출.

## 2. 재부팅 시 프로필이 무조건 크로스코드로 지정됨 ✅ 수정됨

### 증상
- 게임을 자동 감지하고 **프로필 적용**을 누른 뒤 프로그램을 껐다 켜면, 마지막에
  선택/적용한 프로필이 아니라 **항상 크로스코드(CrossCode) 프로필**로 지정됨.
- 그 결과 스텔라리스를 하는데 봇들이 크로스코드 이야기를 하는 게임 오인식이 발생
  (아래 4번 항목과 직접 연결됨).

### 확정 원인 (분석 완료)
자동 감지 오작동이 아니라 **마지막 선택을 디스크에 저장하지 않아 config 기본값으로
되돌아가는 것**이다.

- 재시작 시 초기 게임명은 **항상** `config["capture"]["target_window"]` 에서만
  추출된다 (`src/main.py:280`).
  ```python
  initial_game = config["capture"].get("target_window") or ""
  game_name = _extract_game_name(initial_game)
  ```
- 그런데 `config.yaml:13` 의 `target_window` 기본값이 하드코딩된
  `CrossCode Min v1.4.2-4` → `_extract_game_name` → **"CrossCode"**.
- UI에서 "창 변경 적용"·"프로필 적용"을 누르면 `target_window`/`game_name` 은
  `_settings_queue.put(...)` 로 **런타임 큐에만** 전달된다
  (`src/ui/overlay.py:619, 1777, 1785, 1788`). `src/main.py` 의 while 루프
  (`:65`, `:379`)는 이를 받아 **런타임 변수만 갱신**하고 **config.yaml 에는 저장하지
  않는다.**
- 대조군: vision/chat 모델·STT 설정은 적용 시 `_save_config_vision_provider()` /
  `_save_config_chat_model()` 등으로 **yaml.dump 디스크 저장**된다. 즉 게임 창/프로필
  선택만 이 저장 호출이 빠져 있다.
- 결과: 다음 실행에서 `:280` 이 다시 하드코딩 기본값을 읽어 항상 크로스코드로 폴백.

추가로, "캡처 대상 창"(`target_window`)과 "프로필 게임명"(`game_name`)은 별개 상태로
관리되므로(프로필 적용은 `game_name` 만 큐에 넣음), 복원 시 **두 값을 함께** 다뤄야 한다.

### 해결 방향 (채택: 별도 last_session 상태파일)
`config.yaml`(사용자 기본설정/번들 시딩 대상)을 오염시키지 않기 위해, 마지막 세션
선택만 분리 저장한다.

- `user_data_dir()/last_session.yaml`(혹은 .json)에 마지막 `target_window` 와 적용
  `game_name` 을 저장.
- "창 변경 적용"·"프로필 적용" 시 큐 전송과 함께 이 파일에 기록.
- 시작 시(`main.py`) `target_window`/초기 게임명을 **last_session → 없으면 config 기본값**
  순으로 해석.
- 자동 감지 결과보다 사용자가 명시적으로 "프로필 적용"한 선택을 우선.

### 적용된 수정 (구현 완료)
- `src/utils/paths.py`: `load_last_session()` / `save_last_session(target_window=, game_name=)`
  헬퍼 추가. 상태는 `user_data_dir()/last_session.yaml` 에 UTF-8(yaml)로 병합 저장.
  손상/저장 실패는 조용히 무시하고 기본값으로 폴백(앱 동작을 막지 않음).
- `src/main.py` `main()`: `load_config()` 직후 last_session 으로
  `config["capture"]["target_window"]` 및 `config["capture"]["game_name"]` 을 덮어씀
  → 캡처 프로세스와 AI 프로세스가 모두 같은 config 를 받아 한 곳에서 복원됨.
- `src/main.py` `ai_process`: `config["capture"]["game_name"]`(복원된 명시 선택)이 있으면
  `target_window` 추출보다 **우선** 사용.
- `src/ui/overlay.py`: 창/프로필을 적용하는 6개 큐 전송 지점 모두에 `save_last_session(...)`
  추가 (메인 탭 `_apply_window`/`_apply_profile`/`_regenerate_profile`,
  시작 탭 `_start_apply_window`/`_start_regenerate_profile`).
- `config.yaml` 은 건드리지 않음(번들 시딩 대상 보존).
- 검증: last_session 라운드트립(빈 로드→저장→병합) + 한국어 UTF-8 보존 + 3개 파일
  `py_compile` 통과 확인.

## 3. 캡처된 게임명과 적용된 프로필 이름이 크게 다를 때 경고 없음 ✅ 수정됨

### 증상
- 화면에서 감지한 게임명과 실제 적용된 프로필 이름이 많이 달라도 사용자가 알 수
  없음 (2번 버그를 사용자가 놓치는 원인).

### 적용된 수정 (구현 완료)
- `src/main.py` 에 `_normalize_for_match()` / `_profile_name_mismatch()` 휴리스틱 추가.
  캡처 창에서 추출한 게임명(`_extract_game_name(target_window)`)과 적용된 프로필
  이름(`profile["name"]`)을 정규화(괄호 한국어 병기 제거·기호 제거·소문자) 후 비교.
  한쪽이 다른 쪽을 포함하면 일치로 보고, 아니면 `difflib` 유사도 < 0.5 일 때 불일치로 판정.
- `ai_process._notify_profile_loaded()` 가 불일치 시 경고 텍스트를 `profile_loaded`
  이벤트의 `warning` 필드에 실어 보냄(예: 창은 Stellaris 인데 프로필이 CrossCode).
  채팅창을 어지럽히지 않도록 **상단 타이틀바의 ⚠ 아이콘**으로 표시한다
  (`TitleBar.set_warning`): 평소 숨김, 불일치면 노출 + 툴팁으로 상세, 클릭 시
  설정의 '게임' 탭으로 이동. 일치하는 프로필이 다시 로드되면 자동으로 해제된다.
- AI 프로세스가 `settings_queue` 의 `target_window` 변경을 추적하도록 분기 추가
  (기존엔 캡처 프로세스만 처리했음) → 경고가 최신 창 기준으로 동작.
- 오탐 방지: 창 정보 없음/`Unknown Game`/부분 포함(예: "Hades II" ↔ "Hades")은 경고 안 함.
- 검증: 8개 케이스(핵심 버그 시나리오 경고 + 정상/병기/부분일치 무경고) 전부 통과,
  `py_compile` 통과.

### 향후 개선 후보 (미구현)
- 감지명 ↔ 프로필명 유사도가 낮으면 오버레이/설정 탭에 **경고 표시**.

### 4-1. 같은 말 반복 — 🔬 로그 분석 완료, 원인 재정의됨 (2026-06-29)
- (당초 가설) 할 말이 없을 때 봇이 **페르소나 예제 문구**(`triggers[].reaction`)를
  그대로 재발화한다고 추정.
- **분석 결과 이 가설은 데이터로 반증됨** (`dev_history/log_bk/chat_20260628.log`,
  canonical 출력 1004발화·193라운드 기준):
  - **코드 사실:** `triggers[].reaction`(예: "ㅋㅋㅋㅋㅋ미친ㅋㅋㅋ")은 **채팅
    프롬프트에 아예 주입되지 않는다.** `model_client._build_bots_info()` 는
    `style/emotion/relationship/memory/react` 만 넣는다. `triggers` 는 death/
    boss_clear 이벤트 감지용 데이터일 뿐 LLM 에 전달되지 않음.
  - **(1) 예제 재발화:** 자기 예제와 정확 0.2% / 근사(≥0.8) 0.4% → 사실상 없음.
  - **(2) 자기 직전 발화 반복:** 직전 라운드 대비 연속 중복 0.9%, 전체 누적
    정확중복 0.7% → 드묾. 그나마도 단답 봇(지나가던행인 "흠."/"ㅇㅇ"/"저장 중")에
    집중. 프롬프트에 이미 "이미 나온 문장 복붙 금지" 규칙(`model_client.py:94`)이
    있어 문장 단위 중복은 어느 정도 억제되고 있음.
  - **(3) 진짜 원인 = 소재(클리셰) 쏠림:** "렉" 이 전체 발화의 **5.9%(59/1004)**,
    "술" 2.5%, "저장" 1.9%. 게다가 한 라운드 안에서 여러 봇이 동시에 같은 소재로
    쏠림(로그 라운드 #2~#4 에 워나비/도네요정/분석충/트롤마스터/고인물킹/공익봇/
    공격수가 줄줄이 "렉"). → **체감 "반복"의 정체는 문장 복붙이 아니라 소재 쏠림.**
- **결론: 4-1 의 실효 원인은 4-2("렉 걸린다" 과다 발화)와 같은 뿌리.** 따라서
  "예제 인용 억제 / 직전 발화 필터" 라는 원래 개선안은 효과가 미미하고, 실제
  대책은 4-2 와 묶어 **소재/클리셰 쏠림 억제**여야 한다.
- **개선 후보(미구현, 보류):**
  1. 라운드 내 같은 키워드(렉 등)를 여러 봇이 동시에 못 쓰게 프롬프트 규칙 + 후처리.
  2. 직전 N라운드에 나온 클리셰 표현 빈도 제한.
  3. (단답 봇) 연속 동일 단답은 후처리로 침묵 처리.

### 4-2. "렉 걸린다" 과다 발화 — 4-1 과 동일 뿌리(소재 쏠림)
- 대부분의 봇이 "렉 걸린다"는 말을 함. 특히 ADHD 페르소나가 많이 함.

  최다 클리셰. 한 라운드에서 여러 봇이 동시에 쏠리는 게 핵심 문제. → 4-1 의
  실효 원인과 같으므로 **두 항목을 묶어 '소재/클리셰 쏠림 억제'로 처리**하는 게 맞음.
- 개선 후보: 특정 클리셰 표현 빈도 제한(라운드 내 동시 사용 1~2명 제한 +
  직전 N라운드 빈도 제한). 미구현·보류.
- **수정 (2026-10-15, 4-1 과 함께):** `src/chat/topic_guard.py` 신설.
  1. 프롬프트: 최근 6라운드에 3회 이상 나온 소재를 [최근 채팅에 너무 자주 나온 소재]로 알려 회피.
     규칙에 "같은 소재 최대 2명" + "렉·버그는 화면 정보에 명시됐을 때만" 추가.
  2. 후처리: 라운드 안에서 같은 소재 봇 수 제한(일반 2명, 과열 소재 1명, 호명 봇 면제).
     클리셰 키워드는 `config chat.cliche_keywords`(부분 문자열)로 조정.
  3. 중복 드롭 정규화에서 끝 문장부호 무시("흠." == "흠").
  - 과거 로그(chat_20260628, 1008발화) 재생 시 후처리만으로 "렉" 5.9%→3.3%, 전체 드롭 6.8%.

### 4-3. STT 오인식에 봇이 과반응
- "**기술**"을 "**술**"로만 알아들으면 봇들끼리 술 이야기로 빠짐.
- STT 정확도 문제 + 봇이 오인식 텍스트에 그대로 끌려가는 이중 문제.
- 개선 후보: STT 신뢰도 낮은 토큰 처리, 봇이 단편적 단어에 과몰입하지 않도록 프롬프트 보정.
- **수정 (2026-10-15):** STT 기본값을 `provider: openai` / `model: gpt-transcribe` 로 변경
  (실측 정확도 91% vs gemini-2.5-flash 65%·환각). OpenAI 키가 없으면 `stt.fallback_model`
  (Gemini)로 자동 대체하고 채팅창에 1회 안내. 프롬프트 [최근 스트리머 발화] 섹션에
  "받아쓰기 오인식 가능 — 뜬금없는 단어 하나에 여러 봇이 꽂히지 말 것" 경고 추가.

### 4-4. 방랑객 페르소나가 다른 스트리머 이름을 모름
- 다른 봇/스트리머를 지칭하지 못함 (페르소나 컨텍스트 부족).
- 개선 후보: 현재 활성 페르소나 목록을 각 봇 컨텍스트에 주입.
- **수정 (2026-10-15):** 프롬프트에 [채팅방의 다른 시청자] 섹션(이번 라운드 비발언 봇 이름)
  추가. 페르소나 옵션 필드 `known_streamers`(가상의 스트리머 이름) 신설 → 방랑객에 적용.
  roster 때문에 LLM 이 비발언 봇 채팅까지 지어내던 회귀는 프롬프트 금지문 + `main` 의 발언자 외 채팅 드롭으로 막음.

### 4-5. 대화가 이어지지 않음 ✅ 수정됨 (2026-10-16)
- **증상(2026-10-15 실사용 36라운드):** 말하고 10~20초 뒤에야 반응, 인사("안녕하세요")에 인사한 봇 0명,
  발화 있는 라운드에서도 5명 중 0~2명만 반응, 봇끼리 받아치기 0회, "새벽두부 방송도…" 5회·"라면 땡긴다" 3회.
- **원인:** ① 채팅이 화면 분석 주기에만 생성 ② 발화 반응 규칙이 호명·질문에만 강제 ③ 과열 소재 회피(4-1)가
  지금 장소·상황(보스전 중 '보스')까지 막음 ④ '[타인 반응 빈도] 70~90%' 같은 확률 지시를 LLM 이 못 지킴 +
  발언자 매 라운드 전원 교체 ⑤ 봇별 말버릇 추적 없음 ⑥ STT 가 게임 고유명사를 틀림(크로스워드·에뮬레이터).
- **수정:** 발화 즉시 반응 라운드(`stt.instant_reply`, 설정 음성 페이지 스위치) + `src/chat/flow.py`
  (직전 발언자 carry-over, 코드가 고르는 받아치기, 라운드 대화 과제, 현재 소재 회피 면제, 말버릇 금지·드롭,
  프로필 고유명사 → 받아쓰기 힌트, 프로필 `stt_terms`).
- **샘플 리플레이(seed 7):** 반응 지연 13.0→8.4초, 봇끼리 호출 0→16, 말버릇 5→1. 채팅 비용 $0.14→$0.26/h.
  자세한 수치: `docs/wiki/evaluation.md`.

### 4-6. 봇이 게임 사실을 틀리게 답함 👍 허용 (2026-10-23)
- 예(리플레이 2026-10-16): "여기가 시트론의 집이죠?"에 "홈스테드는 레아 집 맞아" — 실제로는 동료 집일 수 있는데
  봇이 단정. 프로필에 없는 세부(누구 집·NPC 이름)를 물으면 그럴듯하게 지어 답한다.
- 4-5 에서 "질문엔 구체적으로 답하라"를 강화한 부작용도 섞여 있다(모르면 회피 금지 → 추측 단정).
- 개선 후보: 프로필에 없는 사실은 "~였나?"처럼 추측 말투로만 / 고인물 봇만 단정 허용 / 화면 글자(대화창)를
  근거로 할 때만 단정.

### 4-7. 봇이 없는 이름을 지어냄 👍 허용 (2026-10-23)
- 예: "민우 집 아냐?"(리플레이), 과거 "Bergen Village" 등은 실제 지명이었으나 판정이 어렵다.
- 개선 후보: 프롬프트에 "사람·장소 이름은 [게임 정보]·화면 글자·채팅에 나온 것만" 규칙 + 후처리로 프로필에
  없는 고유명사 감지(오탐 위험 — 먼저 로그로 빈도 측정).
- **결정 (2026-10-23):** 봇이 꼭 맞는 답을 할 필요는 없다 — 실제 시청자도 헛소리한다. 사실 단정·맞장구를 막는
  프롬프트 규칙은 넣었다가 뺐다(4-6/4-7 은 허용). **예외: 고인물 봇은 정확해야 한다** → 페르소나 옵션 `accurate: true`
  (고인물킹에 적용)이면 봇 라인에 `[정확한 정보] true — [게임 정보]·화면 글자에 적힌 사실만…` + 규칙 블록 예외 문구.
  - 확인(gpt-6-luna, 고인물킹 호명 질문 4종×2회): 규칙 블록에만 둘 땐 근거 없는 답 지어냄 6/8("홈스테드는 레아의 집",
    "흐린·베오울프 쪽", "베르겐 산길") → **봇 라인에 직접 적으니** 지어냄 1/8(진행 순서 "마룬 밸리"), 모르면 "확실치 않네요".
  - 한계: 프로필에 없는 건 정확히 말할 방법이 없어 "확실치 않네요"가 잦아진다 — 고인물답게 하려면 프로필에 진행 순서·
    자주 묻는 사실을 더 적어야 함. 프로필 자체가 애매한 것도 있음(첫 던전: 마름모 던전 '시험 던전' vs 사원 광산 '첫 던전').
  - **웹 검색 추가 (2026-10-23):** 프로필에 없는 질문은 고인물킹이 "찾아볼게요" 후 5~10초 뒤 검색한 답을 올린다
    (`src/chat/lookup.py`, 설정 'AI 모델 · 키' → '고인물 봇 웹 검색'). 찾은 답은 세션 동안 기억해 같은 질문은 재검색 안 함.
    검색 답도 틀릴 수 있다 — 예: "레아 집이요"(홈스테드)는 확인 안 됨. 측정은 `docs/wiki/models-and-providers.md`.
  그 밖에 버그성 원인 두 가지만 고침:
  1. `flow.speech_kind` 질문 판정을 좁힘 — 의문사만 보고 서술문("어떻게 구워줬던 걸로 기억하는데")까지 질문으로 판정해
     "구체적으로 답하라"를 붙이던 문제. 서술 어미(~데/~다/~네, 끝의 군말 "뭐")·감탄 "어?"는 제외.
  2. 화면 분석 컨텍스트에 '플레이어 캐릭터: 레아' 줄(프로필 인물 중 '주인공') — 주인공을 '파란 아바타'로 적어
     프로필의 다른 인물('파란색 아바타')과 헷갈리던 문제. 크로스코드 프로필 항목명도 '의문의 아바타'로 변경.
     리플레이(seed 7)에서 주인공을 '레아'로 부른 라운드 2/20 → 18/20.

### 4-9. 여러 말·질문을 한 번에 하면 답이 섞이거나 빠짐 ✅ 수정됨 (2026-10-23)
- 증상: "이 광장 이름이 뭐였죠? 그리고 여러분 저녁 뭐 드셨어요?" → 한 봇이 "마름모 광장! 저녁은 카레"처럼 몰아서 답하거나,
  "이 게임 해본 사람 있어요? 다음 던전은? 상점부터 가봅시다." 에서 첫 질문엔 아무도 답 안 함.
- 수정: `flow.split_topics` 가 새 발화를 주제 단위로 나누고(질문·계획·인사 문장마다, 뒤따르는 서술은 앞 주제에 붙임,
  "어허." 같은 군말 제외), `flow.assign_topics` 가 주제별 담당 봇을 정해 [이번 라운드 대화 과제]에 적는다.
  주제는 질문·인사 > 계획 > 서술, 같으면 최근 말 우선으로 최대 3개. 이름 불린 봇은 그 말, 주제마다 최소 1명,
  [스트리머 발화 반응] 높은 봇부터 배정. 주제가 1개면 기존 문구 그대로.
- 확인(gpt-6-luna, 질문 2~3개 섞인 발화 3개): 배정 전엔 몰아 답하기 2건·무응답 질문 1개 → 배정 후 질문마다 답이 달리고
  한 채팅엔 한 주제. 배정된 봇이 가끔 침묵하거나 딴 얘기를 하는 건 남아 있음.

### 4-8. 실제 마이크에서 반응 지연·비용 미검증 ⚠
- 4-5 수치는 샘플 리플레이(쉬지 않고 해설하는 녹음)와 가짜 클라이언트 스모크(마지막 말 2초 뒤 반응)로만 확인.
- 확인할 것: 실제 방송에서 말 → 채팅 표시까지 체감 지연, 발화 즉시 반응 라운드 빈도, 설정 '사용량' 탭의 실제
  채팅 비용(예상 최대 약 2배). 너무 잦으면 `stt.instant_min_gap_seconds`·`instant_max_wait_seconds` 조정.

### 4-10. 고인물 웹 검색 — 실제 앱 미검증 ⚠ (2026-10-23)
- 검증한 것: 실제 API 스크립트(라운드 흐름 흉내)로 '찾아볼게요' → 7~18초 뒤 검색 답, 게임 무관 질문 SKIP, 같은 질문 재검색 안 함.
  검색 모델은 채팅 provider 와 상관없이 gpt-6-luna(OpenAI 키 있을 때) 확인.
- 못 한 것: 실제 앱(`run.bat`)·실마이크 — 말 → '찾아볼게요' → 답 표시 타이밍, 오버레이에 답이 뜨는지(`ui_queue`·`broadcast`),
  설정 스위치 끄고 켜기, 사용량 탭 '웹 검색' 항목, 실제 검색 요금. 로그 `logs/session_*.log` 의 "웹 검색 고인물킹 (…s)" 줄로 확인.
- 남은 문제: 채팅 모델이 gemini-2.5-flash-lite 면 같은 질문을 다시 했을 때 고인물킹이 기억한 답(봇 라인 '이 봇이 검색해 둔 정보')을
  안 쓰고 엉뚱하게 답함("홈스테드에선 잠시 쉬어가세요"). gpt-6-luna 채팅은 정상. 고치려면 기억한 답이 있는 질문은
  검색 답처럼 코드가 직접 올리거나 라운드 과제에 "이 답을 다시 말한다"로 지시.
- 검색 답 사실 확인 안 됨: "홈스테드 = 레아 집", "마룬 밸리 거쳐 바키 쿰".

- **원인(코드 확인):** 스크롤 부족이 아니라 **메시지가 물리적으로 삭제됨.**
  `overlay.py` `_add_message`/`_add_stt_message`가 `max_messages`(기본 50) 초과 시
  `self._list.takeItem(0)`으로 가장 오래된 줄을 영구 제거 → 스크롤 올려도 없음.
  봇 메시지와 STT 인라인이 **같은 리스트·같은 한도를 공유**해서, STT '항상 보기'를
  켜면 실제 대화 보존량이 50보다도 줄어듦. 게다가 `max_messages`는 **설정 UI가 없어**
  사용자가 조절 불가였음.
- **별개(혼동 주의):** 모델 프롬프트에 들어가는 과거는 `model_client`의 `chat_history[-10:]`
  로 최근 10개 고정 — 이건 토큰/일관성 축이지 "화면에 안 보임"의 직접 원인은 아님(5-2/토큰 영역).
- **수정 (2026-06-29):**
  - `config.yaml` `ui.max_messages` 기본값 **50→150** 상향(QListWidget은 수백 개 가벼움).
  - 설정 '음성' 탭 부가기능에 **"채팅 기록 표시 개수" 스핀박스(50~500)** 추가.
    `_save_max_messages`가 `update_user_config("ui",...)` 저장 + `on_max_messages_changed`
    콜백 → `OverlayWindow.set_max_messages`로 **런타임 즉시 반영**(현재 리스트도 새 한도로
    즉시 트리밍, 재시작 불필요). STT 토글과 동일한 콜백 패턴.
  - `_add_message`/`_add_stt_message`의 폴백 기본값도 50→150으로 통일.
- **남은 일:** STT 인라인과 봇 메시지의 카운트 분리(STT가 봇 대화 보존을 잠식하지 않게)는
  미적용 — 필요 시 후속. `chat_history[-10:]` 확대도 별도 검토 대상.

### 5-1b. 게임 프로필 생성이 503에도 끝까지 진행돼 빈 프로필 저장됨 ✅ 수정됨
- **증상:** gemini-3.5-flash 등 신모델이 고수요로 503("high demand")을 뱉을 때,
  프로필 생성의 각 단계가 독립 `try/except` 라 한 단계가 재시도까지 실패해도
  다음 단계로 계속 진행 → 거의 빈 프로필이 디스크에 저장되고, 다음 실행 때 그
  빈 파일이 로드돼 재생성 기회를 잃음. 단계당 백오프도 4→8→16→30s 라 한 단계에
  ~1분, 5단계면 ~5분을 503에 갈려 씀.
- **원인:** 503은 모델 자체의 일시적 과부하라 같은 순간 같은 모델로 재시도해도
  계속 막혀 있을 공산이 큼(쿼터 429와 다름).
- **수정 (2026-06-29):**
  - `_search` 재시도를 **3회·2→4s(상한 8s)** 로 단축(기존 5회·~58s → ~6s).
  - `ProfileGenerationAborted` 예외 추가: 한 단계가 **503 등 재시도성 오류**로
    소진 실패하면 나머지 단계를 시도하지 않고 **생성 전체를 즉시 중단**.
    (JSON 파싱 실패 등 비재시도성 오류는 종전대로 그 단계만 기록하고 계속.)
  - `load_profile` 이 이 예외를 잡아 **빈 yaml 을 저장하지 않고** `_empty_profile`
    에 `_generation_aborted` 플래그만 실어 반환(빈 파일 박제 방지).
  - **설정창 상태 표시(이번 핵심 요청):** `main._notify_profile_loaded` 가 결과를
    `ok`/`partial`/`aborted` 로 분류해 `profile_loaded` 메시지에 `status`+`detail` 동봉.
    `overlay.set_profile_name(name, status, detail)` 이 '게임' 탭과 시작 탭 ③ 라벨을
    **색상으로 상시 표시** — 🟢정상 / 🟡일부 누락(partial) / 🔴503 중단(aborted, 임시 빈 프로필).
    재생성 클릭 시 🟡"재생성 중"으로 초기화돼 직전 빨강이 남지 않음.
- **남은 일:** 폴백 모델 자동 전환은 사용자 요청으로 **넣지 않음**(원하면 'AI 모델'
  탭에서 gemini-2.5-flash 등으로 직접 변경). 필요 시 후속 검토.
