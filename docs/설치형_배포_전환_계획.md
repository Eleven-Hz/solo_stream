# 계획 — 설치형(포터블) 배포 전환

> **목표:** Python/venv가 없는 Windows 사용자도 압축만 풀면 실행되는 **단일 폴더 포터블** 배포물 제작.
> **결정 사항(사용자 확정):**
> - 방식: **PyInstaller `onedir`**(단일 폴더 포터블). installer/onefile 아님.
> - API 키: **사용자가 첫 실행 시 직접 입력** → 사용자 폴더에 저장. 키를 빌드에 포함하지 않음.
> - 대상: **불특정 다수**(Windows). SmartScreen/백신 오탐·권한 문제까지 고려.
> - 개발 지속: **배포 이후에도 개발 계속** → 개발 편의를 리팩터링 제약으로 둠(아래 DEV 모드 참조).

## 0. 왜 "그냥 PyInstaller 돌리기"로 안 되는가 (진단)

코드 조사로 확인된 패키징 차단 요소.

| # | 문제 | 현재 코드 위치 | 동결(frozen) exe에서의 결과 |
|---|------|----------------|------------------------------|
| 1 | 경로가 `__file__` 루트 기준으로 하드코딩 (총 9곳) | `config_loader.py:7`, `logger.py:6,46`, `game_profile_loader.py:23`, `persona_loader.py:32`, `overlay.py`(8곳) | `parent.parent.parent` 구조가 깨져 config/persona/profile **로드 실패** |
| 2 | 런타임 **쓰기**가 다수 발생 | overlay의 config.yaml dump(여러 곳), `.env.local` 저장(`overlay.py:1276`), `game_profiles/` 생성(`game_profile_loader.py:192,211`), `logs/`(`logger.py`) | 포터블 폴더가 읽기전용 위치(Program Files 등)면 **권한 오류로 저장 실패** |
| 3 | PyTorch + silero 모델 의존 | `vad.py:34,48,56` (`import torch`, `load_silero_vad`) | torch 미수집 시 STT 크래시 / silero 모델 파일(`.jit`/`.onnx`) 미포함 시 로드 실패. 번들 최대 크기 요인 |
| 4 | 멀티프로세싱 spawn 프로세스 3개 | `main.py:705,711,719` (`multiprocessing.Process` ×3) | `freeze_support()` 없으면 자식이 앱 전체를 무한 재실행. **현재 `main.py:765`에 이미 있음 ✓** — 추가로 자식의 함수내 import 패턴(AGENTS.md 규약)이 frozen 환경에서도 유지되는지 검증 필요 |
| 5 | 무거운/동적 import 패키지 | `google-genai`, `PyQt6`, `scikit-image`, `sounddevice`/`soundfile`, `pywin32`(`win32gui` 등) | PyInstaller 자동 분석이 놓치면 런타임 `ModuleNotFoundError` / DLL 누락 |

**결론:** 핵심 난이도는 **Phase 1(경로 추상화)**. 이게 안 끝나면 빌드가 성공해도 실행 단계에서 전부 깨진다. 작업량의 약 60%.

## Phase 1 — 경로 추상화 (리팩터링, 빌드 전 필수)

앱이 "어디서 실행되든"(스크립트 / frozen onedir) 올바른 위치를 찾도록 단일 모듈로 통합.

### 1-1. `src/utils/paths.py` 신설 — 두 가지 루트 개념 분리

- **`resource_dir()`** — 읽기전용 번들 리소스.
  - `getattr(sys, "frozen", False)` 이면: onedir 기준 `Path(sys.executable).parent`(또는 `sys._MEIPASS`).
  - 아니면(스크립트 실행): 기존 프로젝트 루트.
  - 대상: 기본 `config.yaml`, `personas/*.yaml`, 번들 `game_profiles/default.yaml`, silero 모델.
- **`user_data_dir()`** — 쓰기 가능한 사용자 폴더.
  - 기본: `%APPDATA%\SoloStream\` (`os.getenv("APPDATA")`).
  - **DEV 모드 분기**: 환경변수 `SOLO_STREAM_DEV=1` 이면 `%APPDATA%`를 무시하고 **프로젝트 루트**를 반환 → 개발 중엔 지금처럼 프로젝트 폴더의 config/game_profiles/logs를 직접 읽고 쓴다(동작 100% 동일, "기본값 바꿨는데 안 보임" 함정 제거).
  - 대상: 사용자 `config.yaml`, `.env.local`, `game_profiles/`(자동 생성), `logs/`.
- **`ensure_user_data()`** — 최초 실행 시딩.
  - user_data에 `config.yaml`/`personas/`가 없으면 `resource_dir()`에서 복사.
  - `game_profiles/`, `logs/` 디렉터리 생성.
  - DEV 모드면 user_data == 프로젝트 루트이므로 시딩이 사실상 no-op(이미 파일이 있음).

#### DEV 모드 결정 배경 (확정)
- 개발은 배포 이후에도 계속 진행 → 개발 편의가 리팩터링의 제약 조건.
- frozen 여부로만 자동 분기하면 "배포본의 `%APPDATA%` 동작"을 개발 중 재현하려면 매번 exe를 빌드해야 함.
- 그래서 **명시적 `SOLO_STREAM_DEV` 플래그**를 둬서: 평소 개발 = 프로젝트 폴더(지금과 동일), 플래그 끄고 exe 테스트 = `%APPDATA%` 동작 재현.
- `run.bat` / `run_debug.bat`에 `set SOLO_STREAM_DEV=1` 한 줄 추가.

### 1-2. 하드코딩 경로 9곳을 `paths` 호출로 교체

- 읽기 → `resource_dir()` 우선, 사용자 오버라이드 있으면 `user_data_dir()`.
- 쓰기(config dump, .env.local, game_profiles, logs) → **반드시 `user_data_dir()`**.
- 교체 대상 파일: `config_loader.py`, `logger.py`, `game_profile_loader.py`, `persona_loader.py`, `overlay.py`.
- `config_loader.py`의 `load_config`는 "사용자 config 우선 → 없으면 번들 기본" 순서로 변경.
- `.env.local` 로드 경로(`config_loader.py:8`)도 `user_data_dir()` 기준으로.

### 1-3. 개발 규칙 (리팩터링이 도입하는 유일한 새 규칙)

> **새 파일 입출력은 `Path(__file__)...`을 직접 쓰지 말고 `paths` 모듈을 거친다.**
> - 읽기전용 리소스 → `paths.resource_dir()`
> - 쓰기/사용자 데이터 → `paths.user_data_dir()`

- 규칙은 이 하나뿐. `AGENTS.md`(루트 + `src/utils/AGENTS.md:27`)에 한 줄로 명시.
- 경로 한 곳을 바꿀 때 9곳 수정 → 1곳 수정으로 줄어드는 **유지보수 개선**이므로 개발이 더 쉬워짐.

### 1-4. 검증 (스크립트 모드 회귀)

- 리팩터링 후 **기존 `run.bat` 실행이 그대로 동작**하는지 먼저 확인(DEV 모드 = 지금과 동일 경로).
- `src/utils/AGENTS.md:27`의 utils 경로 가정 메모도 갱신.

## Phase 2 — PyInstaller 빌드 스펙

### 2-1. 개발 의존성 + spec 작성

- `pyinstaller` 추가(런타임 requirements와 분리: `requirements-build.txt` 권장).
- `solo_stream.spec`:
  - 진입점 `src/main.py`, **`--windowed`**(콘솔 없음 — 현재 pythonw 역할 대체).
  - `name="SoloStream"`.

### 2-2. `datas` (번들 데이터)

- 기본 `config.yaml`, `personas/*.yaml`, `game_profiles/default.yaml`.
- **silero-vad 모델 파일**: `importlib.util.find_spec("silero_vad")`로 패키지 경로를 찾아 모델(`.jit`/`.onnx`) 포함. (`load_silero_vad()`가 패키지 내부 파일을 참조하므로 누락 시 실패.)

### 2-3. `hiddenimports` / `collect_all`

- `collect_all`: `torch`, `scikit-image`(skimage), `google.genai`.
- hiddenimports: `win32gui`, `win32api`, `win32con`(pywin32 동적), `sounddevice`/`soundfile`(번들 DLL `binaries`까지), `anthropic`, `openai`.
- skimage의 동적 서브모듈 / google-genai의 lazy import 누락 주의.

### 2-4. torch 슬림화 (번들 크기 결정)

- silero-vad는 **CPU torch만** 필요. CUDA 포함 빌드면 1GB+ → CPU-only로 약 300MB대.
- 빌드 venv에 `torch` CPU 휠 설치(`--index-url .../cpu`) 후 패키징.

## Phase 3 — 첫 실행 온보딩 (API 키 입력)

- 시작 시 `user_data_dir()/.env.local`에 키가 없으면:
  - 옵션 A(권장): 기존 overlay **설정 패널의 "API 키 저장" UI**(`overlay.py:581`, `_save_api_keys` `overlay.py:1273`)를 첫 실행 흐름에서 먼저 노출.
  - 옵션 B: 경량 키 입력 다이얼로그를 메인 시작 전에 표시.
- 키 미설정 상태에서 **크래시 대신 graceful degrade**: AI/STT 비활성 + 안내 메시지. (`config_loader.get_api_key`가 현재 `ValueError` raise — frozen에서 콘솔 없으면 조용히 죽으므로 사용자 안내로 전환.)

## Phase 4 — 빌드 자동화 & 배포물

- `build.bat`(또는 `build.ps1`): clean(`build/`, `dist/`) → `pyinstaller solo_stream.spec` → 산출 `dist/SoloStream/`.
- 배포 zip 구조:
  ```
  SoloStream/
    SoloStream.exe
    _internal/            # onedir 의존성
    사용설명.txt          # API 키 발급/입력 + SmartScreen 안내
  ```
- `.gitignore`에 `build/`, `dist/` 산출물 정리(spec 자체는 추적).

## Phase 5 — 검증 (불특정 다수 배포 대응)

1. **Clean-room 테스트**: Python/venv 없는 환경(또는 다른 Windows 사용자 계정)에서 압축 해제 후 실행.
   - 캡처 / 오버레이 / 채팅 / STT 각각 동작.
   - **멀티프로세싱 자식 재실행 폭주(무한 창 생성) 여부 집중 확인** — frozen + spawn의 대표 함정.
   - `%APPDATA%\SoloStream\`에 config/profile/logs가 정상 생성·쓰기되는지.
   - (DEV 모드 OFF로 exe 테스트 → 배포본과 동일 경로 동작 확인.)
2. **SmartScreen / 백신**:
   - 코드서명 인증서 없음 → 첫 배포는 "추가 정보 → 실행" 안내를 `사용설명.txt`에 명시.
   - 코드서명(EV/OV 인증서)은 **비용 동반 → 별도 의사결정 항목**으로 분리(이번 범위 밖).
