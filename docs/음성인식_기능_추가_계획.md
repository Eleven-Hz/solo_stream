# 음성 인식(STT) 기능 추가 계획

> 사용자(스트리머) 마이크 음성을 텍스트화하여 vision 라운드의 봇 채팅 생성 컨텍스트로 합류시킨다.
> 본 코드 반영 전에 `tests/stt/` 디렉토리에서 단독 검증을 우선한다.

---

## 1. 목표 및 범위

- **목적**: 사용자 마이크 음성 → STT → vision 라운드 시 함께 프롬프트에 포함하여 봇이 사용자의 멘트에 반응하도록 한다.
- **엔진**: `silero-vad`(로컬 발화 구간 검출) + `google-genai` Gemini Audio API(transcribe)
- **타이밍**: vision 라운드와 **동기**. 발화는 버퍼에 누적되고, AI 프로세스가 라운드를 시작할 때 그동안 쌓인 transcript를 drain하여 프롬프트에 합친다.
- **트리거 정책**: 발화 자체가 vision 라운드를 트리거하지 않는다. 음성은 어디까지나 vision 컨텍스트의 보조 입력으로만 사용한다.
- **테스트 우선**: `tests/stt/` 독립 테스트로 정확도·지연·VAD 동작을 먼저 확인한 뒤 본 코드 통합한다.

### 비범위(Out of scope)

- 봇 호출(@봇이름) 인식, 음성 명령 처리는 본 계획에 포함하지 않는다(추후 Phase).
- 시스템 오디오(게임 사운드/NPC 대사)는 인식 대상이 아니다. 마이크만 다룬다.

---

## 2. 의존성 추가

`requirements.txt`에 추가:

- `silero-vad` — 발화 구간 검출 (PyTorch 모델 기반)
- `sounddevice` — 마이크 실시간 캡처
- `soundfile` — WAV 입출력, 16kHz 모노 정규화
- `numpy` (이미 존재) — PCM 버퍼 조작

> MP3 입력이 필요할 경우 `pydub`을 추가하고 시스템에 ffmpeg가 있어야 한다. 1차 검증에서는 **WAV만 지원**하고 MP3 지원은 검토 후 결정한다.
> `google-genai`는 이미 사용 중이므로 추가 설치 없음.

## 3. 테스트 디렉토리 구조 (`tests/stt/`)

`tests/vision/` 패턴을 그대로 따라 동일한 워크플로(러너 + DB + HTML 리포트)를 적용한다.

```
tests/stt/
  config.yaml      # 테스트 설정 (입력 소스, VAD/STT 모델 파라미터)
  run.py           # 테스트 러너
  audio/           # 사용자가 녹음한 .wav 샘플
  db.py            # SQLite: session / segment / result 테이블
  report.py        # HTML 리포트 (audio 태그로 segment 재생 가능)
  results.db
  result_*.txt
```

### 3.1 `tests/stt/config.yaml` 예시

```yaml
input:
  mode: file                              # file | mic | video_audio
  file: tests/stt/audio/sample01.wav      # mode: file 일 때
  duration_seconds: 30                    # mode: mic 일 때 최대 녹음 시간
  video: tests/video/crosscode_video_01.mkv  # mode: video_audio 일 때

vad:
  threshold: 0.5
  min_speech_ms: 250
  min_silence_ms: 500
  sample_rate: 16000

stt:
  provider: gemini
  model: gemini-2.5-flash
  language: ko
  prompt: "사용자가 게임을 플레이하며 한국어로 혼잣말/감상을 말합니다."

output:
  file: tests/stt/result.txt
  description: "STT 1차 정확도 테스트"
  append: false
```

### 3.2 테스트 러너 흐름 (`tests/stt/run.py`)

1. **입력 로드**
   - `mode: file` — WAV 파일을 16kHz mono numpy로 디코딩.
   - `mode: mic` — `sounddevice`로 N초간 녹음 후 numpy 변환.
   - `mode: video_audio` — `cv2` 또는 ffmpeg로 비디오 트랙에서 오디오 추출. vision 영상과 동일 파일을 입력해 시간 정렬 검증이 가능.
2. **VAD 분할** — silero-vad로 발화 segment 리스트 추출, `(start_s, end_s, pcm)` 형태로 보관.
3. **Transcribe** — segment마다 Gemini Audio 호출 → 텍스트 + 응답시간 측정.
4. **DB 저장** — `session` / `segment(audio_blob)` / `result(transcript, elapsed)` 스키마로 저장.
5. **출력** — `result_*.txt`(콘솔용)와 `result_*.html`(audio 재생 가능한 리포트)을 생성.

### 3.3 DB 스키마

```sql
CREATE TABLE session (
  id INTEGER PRIMARY KEY,
  started_at TEXT,
  description TEXT,
  source TEXT,           -- file:path / mic / video_audio:path
  stt_model TEXT,
  vad_threshold REAL
);
CREATE TABLE segment (
  id INTEGER PRIMARY KEY,
  session_id INTEGER,
  start_s REAL,
  end_s REAL,
  audio_blob BLOB        -- WAV 인코딩
);
CREATE TABLE result (
  segment_id INTEGER,
  transcript TEXT,
  elapsed REAL
);
```

## 4. 본 코드 모듈 설계 (`src/stt/`)

테스트에서 검증된 컴포넌트를 그대로 옮겨 패키지화한다.

```
src/stt/
  __init__.py
  vad.py            # SileroVAD 래퍼
  recorder.py       # sounddevice 기반 마이크 → 16kHz mono 링버퍼
  transcriber.py    # Gemini Audio 클라이언트 (src/ai/model_client.py 패턴 차용)
  pipeline.py       # VAD + Recorder + Transcriber 통합
```

### 4.1 핵심 인터페이스

**`src/stt/vad.py`**

```python
class SileroVAD:
    def __init__(self, threshold=0.5, sample_rate=16000,
                 min_speech_ms=250, min_silence_ms=500): ...
    def iter_speech_segments(self, pcm: np.ndarray) -> Iterator[tuple[float, float, np.ndarray]]:
        """(start_s, end_s, segment_pcm)"""
```

**`src/stt/transcriber.py`**

```python
class GeminiTranscriber:
    def __init__(self, api_key: str, model: str, language: str = "ko",
                 prompt: str | None = None): ...
    def transcribe(self, pcm: np.ndarray, sample_rate: int) -> str:
        """PCM → WAV 인메모리 인코딩 → Gemini Audio 호출."""
```

**`src/stt/pipeline.py`**

```python
class STTPipeline:
    def __init__(self, vad: SileroVAD, transcriber: GeminiTranscriber,
                 sample_rate: int = 16000): ...
    def start(self, on_segment: Callable[[float, float, str], None]) -> None:
        """마이크 캡처 시작. 발화 감지 후 transcribe 결과를 콜백으로 전달."""
    def stop(self) -> None: ...
```

## 5. 본 코드 통합

### 5.1 `config.yaml` 확장

기존 `stt` 섹션을 다음과 같이 확장한다.

```yaml
stt:
  enabled: true
  mode: vad
  sample_rate: 16000
  vad_threshold: 0.5
  min_speech_ms: 250
  min_silence_ms: 500
  buffer_seconds: 20      # vision 라운드 사이 누적 가능한 transcript 길이
  model: gemini-2.5-flash
  language: ko
  device: default         # sounddevice 입력 장치 (None=시스템 기본)
```

### 5.2 프로세스 구조 변경

기존 구조:

```
Capture → (image_queue) → AI → (ui_queue) → UI
```

확장 후:

```
Capture → (image_queue) ─┐
                          ├→ AI Process → (ui_queue) → UI
   STT → (stt_queue) ────┘
```

- **STT 프로세스 신설**: `stt_process(stt_queue, settings_queue, config, api_key)`
  - `STTPipeline`을 사용해 마이크 발화 감지 시마다 `{"timestamp": float, "text": str, "duration": float}`을 `stt_queue`에 put.
  - 기존 `capture_process`와 동일하게 `chat_active` 설정에 반응(시작/정지).
- **AI 프로세스 수정**: vision 라운드 시작 직전 `stt_queue`를 non-blocking으로 drain → 최근 `buffer_seconds` 이내의 발화만 추려 프롬프트 빌더에 넘긴다. 라운드 종료 시 사용된 transcript는 버린다.

### 5.3 채팅 프롬프트 변경

`src/chat/orchestrator.py` 또는 chat 클라이언트의 프롬프트 빌더에 사용자 발화 섹션을 추가한다.

```
[게임 상황]
...

[사용자 발화 (최근)]
- (12.4s 전) "와 이 보스 진짜 어렵네"
- (3.1s 전) "약점이 어디지"

[채팅 생성 지침]
...사용자가 직접 한 말은 봇이 들은 것으로 간주하고 자연스럽게 반응할 수 있다...
```

### 5.4 UI

1차 통합에서는 `config.yaml`로만 STT를 활성/비활성한다. UI 토글, 마이크 장치 선택, 발화 표시는 후속 작업으로 둔다.

## 6. 마일스톤

| 단계 | 내용 | 산출물 |
|---|---|---|
| M1 | VAD + Transcribe 단위 검증 (WAV 파일 입력) | `tests/stt/run.py` mode=file 동작, HTML 리포트 |
| M2 | 실시간 마이크 모드 | mode=mic 추가, 콘솔 실시간 출력 |
| M3 | 영상 음성 추출 모드 | mode=video_audio, 기존 게임 영상 + 사용자 녹음 합쳐 종합 검증 |
| M4 | 본 코드 통합 | `src/stt/` 이전, `main.py`에 STT 프로세스, vision 라운드와 합류 |
| M5 | 프롬프트 튜닝 | 사용자 발화에 봇이 자연스럽게 반응하는지 페르소나별 검증 |

## 7. 미해결 결정 사항

- **MP3 지원 여부**: ffmpeg 의존을 피하기 위해 1차에서는 WAV만 지원. 필요 시 M2~M3에서 재논의.
- **Gemini Audio 비용·지연**: segment마다 호출이 부담이면 라운드 단위로 묶어 일괄 호출하는 옵션을 검토. 단, 시간 정렬·화자 라벨링 필요.
- **연속 발화 분절 품질**: silero-vad의 `min_silence_ms`로 문장 단위 분할이 자연스러운지 M1에서 확인. 너무 잘리면 후처리로 인접 segment 병합 로직 추가.
- **마이크 장치 자동 선택**: 사용자 환경에서 기본 입력 장치가 어떤 식으로 잡히는지 M2에서 확인 후 UI 선택 UX 결정.

---

## 8. 리스크

- **PyTorch 의존 증가**: silero-vad가 PyTorch에 의존하므로 설치 용량이 늘어난다. CPU 전용 빌드로 한정해 부담을 최소화한다.
- **마이크 권한/장치 충돌**: 다른 앱이 점유 중이면 sounddevice가 실패할 수 있다. 시작 시 명확한 에러 메시지를 띄운다.
- **STT 오인식이 봇 채팅을 망가뜨릴 위험**: transcript가 빈 문자열이거나 신뢰도가 낮을 때 프롬프트에 포함하지 않는 필터를 둔다.
